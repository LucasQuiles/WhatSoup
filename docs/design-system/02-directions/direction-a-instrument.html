05

Annotations

Why this direction, and the mechanics underneath it.

Direction thesis — Instrument

A fleet console is closer to a cockpit than a website. Direction A bets that structure drawn with hairlines — not filled cards — plus mono-forward numerics and annunciator status discipline reads as engineered trust. The chassis is near-monochrome graphite; the six semantic channels (3 modes, 3 statuses) are the only chromatic vocabulary; one signal-orange accent marks “the operator’s next move” and nothing else. Healthy is quiet: an all-green fleet shows almost no color at all, so the single warn diamond on sales is unmissable within the 5-second scan. No textures, no glass, no gradients — restraint is the polish.

Wordmark: SOUP as a faceplate engraving — IBM Plex Mono, 0.42em spaced caps, one orange tick. No bowl, no mascot.

Token architecture (the CSS above is the spec)

Three tiers: --p-* primitives (raw graphite/paper/chromatic values — never consumed by components), --s-* semantic roles remapped under html[data-theme], and component tokens only on deviation. ~70 semantic tokens cover the whole sheet.

  • Surfaces: inset / base / raised / overlay — a 4-rung ladder per theme.
  • Elevation law: dark elevates by lightening; light by shadow + hairline at near-constant luminance.
  • Borders: white-alpha (dark) vs re-derived black-alpha (light) — no shared hex anywhere.
  • Status/mode: 4-strength mini-scales (wash/border/solid/fg) × 2 themes; --s-ok-* ≠ --s-mode-passive-* by role AND value (closes P2-12).
  • Focus/action: --s-focus-ring and the primary fill are separate roles that happen to share the accent today — free to diverge per theme tomorrow.

Verdict: retire “Soup Kitchen.” An instrument panel does not have a kitchen; the brand’s warmth survives entirely in the SOUP plate and the tone of voice. One term per concept, enforced by the vocabulary table in the v3 spec (closes P2-11).

Motion budget & reduced motion

  • instant (0ms): tabs, sorts, toggles, keyboard-initiated anything — instrument switches don’t tween.
  • fast (120ms): reveal-label slide, lamp settle, hover washes.
  • base (180ms): modal/popover in — anchored scale (0.97→1) + fade, ease-out only (cubic-bezier(0.22,1,0.36,1)).
  • slow (280ms): overlay out, large pane settle.
  • ambient: crit-lamp blink (2-step, never a fade), typing dots, skeleton shimmer — the only loops in the system.

@media (prefers-reduced-motion: reduce) zeroes every duration, kills the shimmer and the blink (lamps rest lit), and disables smooth scrolling. Anything animated outside these four tokens is a lint finding.

Accessibility — computed contrast

  • Dark: body text #e9ebed on #0b0c0e = 15.7:1; secondary #9aa1a8 = 7.4:1; ghost 3.4:1 (decorative-only role, lint-restricted, never the sole carrier of information).
  • Light: body text #16181a on #f2f2ef = 15.2:1; secondary #4c5258 = 7.0:1; ghost 3.2:1 (same restriction).
  • Focus ring: orange 2px + 2px offset — 5.0:1 (dark) and 4.6:1 (light) against base; clears the 3:1 non-text floor in both themes.
  • Status is never color-only: lamps carry shape (disc / diamond / square) plus a text readout; pills carry glyphs (●◆■); table rows pair the warn/crit edge with the readout column.
  • AA pairs hold by scale construction (Radix method): text tokens are only permitted on their designated surface tokens, so theme-wide AA is a palette property, not a per-screen audit.

What the control sheet resolves

  • P1-1 → one Button (6 variants × 3 sizes) + one reveal-label mechanic shared by nav/send/add/feed contexts.
  • P1-2 → one Modal anatomy; focus trap + single-fire Escape + focus restore, demoed live above.
  • P1-3 → dual theme via html[data-theme] token swap; zero component branches.
  • P1-4 → one lamp + one mode indicator; shape-coded, text-paired, single source of truth.
  • P1-5 → one Pill primitive (tone × size × static/interactive/removable).
  • P1-6 → tiered tokens; component constants stay component-scoped; orphans deleted by construction.
