### CQ-01 — Centralize SQLite-timestamp epoch-ms parsing (core + fleet copies)
- **Severity/Effort:** P2 / M  ·  **Kind:** duplication  ·  **Confidence:** high  ·  **Partition:** cross-cut
- **Files:** `src/core/lid-resolver.ts`, `src/fleet/health-poller.ts`, `src/fleet/time-utils.ts`

- **Evidence:** core/lid-resolver.ts timestampToEpochMs and fleet/health-poller.ts readTimestampMs are functionally identical: both test /^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}$/, rewrite to `${v.replace(' ','T')}Z`, Date.parse, and return finite ms or null. fleet/time-utils.ts already exports a canonical normalizeTimestamp doing the same SQLite-UTC normalization. - **Risk:** lid-resolver feeds LID-flip ordering and retention; health-poller feeds staleness. A normalization change (e.g. handling ISO strings with offsets that fleet/time-utils accepts but the regex form rejects) could shift comparisons — keep epoch-ms semantics identical and run both modules' tests.
