# PR Metadata Guard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prevent GitHub from auto-closing an issue when a pull-request body or candidate commit message contains an unintended closing-keyword reference.

**Architecture:** Add a standalone fail-closed TypeScript guard rather than expanding the publication-audit scanner. The guard reads a PR body from a local file, stdin, or the checked-out pull-request event payload; it accepts closing directives only in a narrow visible, marker-delimited section, scans the exact Git commit range, and emits only bounded rule codes plus PR/issue numbers. The quality workflow invokes the event-payload mode for pull-request runs, while the local command retains body-file and stdin modes for authors.

**Tech Stack:** Node.js 24.15.0, TypeScript with native type stripping, Vitest, GitHub Actions, Git.

## Global Constraints

- Preserve the current `origin/main` behavior and keep this work limited to issue #2512.
- Do not modify the conflicting open PR #2084 or reuse its branch; its publication-guard rewrite does not own PR metadata.
- Use `scripts/lib/cli-args.ts` for closed-option parsing and `cleanGitEnv` for local Git commands.
- Treat missing, unreadable, malformed, or incomplete CI metadata and unavailable Git ranges as `INCONCLUSIVE` (exit 2), never as a clean result.
- Treat a policy violation as exit 1 and a clean/default-target result as exit 0; a non-default target may warn with exit 0 only when all metadata and range checks succeeded.
- Never echo a PR body, commit message, path, account, host, or arbitrary text. Diagnostics and JSON receipts may contain only bounded rule codes and PR/issue numbers.
- Do not allow closing-keyword prose anywhere outside the exact `<!-- whatsoup:closing-directives:start -->` / `<!-- whatsoup:closing-directives:end -->` section. Inside that section, permit only one canonical directive per line.
- Keep the existing publication guard unchanged; the new guard has its own script, test, public-surface row, workflow step, and pre-push test wiring.
- Run all Node commands through the repository's pinned runner.

### Guard contract

```ts
export type GuardDecision = 'pass' | 'warn' | 'fail' | 'inconclusive';

export interface PrMetadataFinding {
  code:
    | 'pr-metadata.closing-directive-outside-section'
    | 'pr-metadata.invalid-directive-section'
    | 'pr-metadata.commit-closing-directive';
  issueNumbers: number[];
}

export interface PrMetadataReceipt {
  decision: GuardDecision;
  pullRequestNumber: number | null;
  intentionalIssueNumbers: number[];
  findings: PrMetadataFinding[];
  warnings: string[];
}

export function runPrMetadataGuard(
  argv?: readonly string[],
  cwd?: string,
  stdin?: string,
): { exitCode: 0 | 1 | 2; receipt: PrMetadataReceipt };
```

The only accepted directive block is:

```markdown
<!-- whatsoup:closing-directives:start -->
Fixes #123
<!-- whatsoup:closing-directives:end -->
```

Each directive line must match exactly one supported GitHub keyword plus an optional colon and one same-repository `#123` or cross-repository `owner/repo#123` reference. All other lexical closing-keyword matches are findings, regardless of nearby prose, quotation, emphasis, code spans, or negation.

- [ ] **Step 1: Implement closed argument parsing and source selection**

Use a closed option schema:

```ts
const OPTIONS = {
  booleanOptions: ['--stdin', '--json', '--help'],
  valueOptions: ['--body-file', '--github-event', '--base', '--head', '--target', '--default-branch'],
} as const;
```

Require exactly one body source (`--stdin`, `--body-file`, or `--github-event`). Require `--base`, `--head`, `--target`, and `--default-branch` for local body sources. For event mode, derive all four values from the event and reject malformed/missing fields. Convert a null GitHub body to an empty string, but reject a non-string non-null body. Map all file/JSON/input failures to exit 2 without exposing the file path or body.

- [ ] **Step 2: Implement lexical classification and explicit-section validation**

Use one case-insensitive supported-keyword matcher and a separate exact-line directive matcher. Walk body lines while tracking only the start/end markers. For a marker-delimited section, reject duplicate, nested, unmatched, or non-directive nonblank lines. For every closing-keyword match outside the section, emit `pr-metadata.closing-directive-outside-section`; for an invalid section, emit `pr-metadata.invalid-directive-section`. Deduplicate and sort issue numbers before placing them in the receipt.

```ts
const closingReference = /\b(?:close|closes|closed|fix|fixes|fixed|resolve|resolves|resolved)\s*:?[ \t]+(?:(?:[A-Za-z0-9_.-]+\/[A-Za-z0-9_.-]+)?#)([1-9]\d*)\b/gi;
const directiveLine = /^(?:close|closes|closed|fix|fixes|fixed|resolve|resolves|resolved)\s*:?[ \t]+(?:(?:[A-Za-z0-9_.-]+\/[A-Za-z0-9_.-]+)?#)([1-9]\d*)\s*$/i;
```

- [ ] **Step 3: Implement exact commit-range scanning**

Validate both revisions as full SHA-1 or SHA-256 object IDs, require `base` to be an ancestor of `head`, and run only:

```ts
execFileSync('git', ['log', '--format=%B', `${base}..${head}`], {
  cwd,
  encoding: 'utf8',
  env: cleanGitEnv(),
  stdio: ['ignore', 'pipe', 'pipe'],
});
```

Scan the returned bytes without logging them. Any lexical closing reference in the candidate range produces `pr-metadata.commit-closing-directive`, because commit messages have no permitted directive section. A Git failure or non-ancestor range is exit 2.

- [ ] **Step 4: Implement decision and bounded receipt rendering**

Return `fail`/1 for any finding when the target is the default branch; return `warn`/0 for a complete non-default target with findings or a clean non-default target, retaining only `pr-metadata.nondefault-target` plus finding codes and issue numbers. Return `pass`/0 only for a complete clean default-target check. Return `inconclusive`/2 for input/range failures. In `--json` mode print the receipt JSON; otherwise print only `PR_METADATA_GUARD <decision> <code> pr=<number> issues=<numbers>` lines. Never include raw body or commit content.

- [ ] **Step 5: Run the focused suite and verify GREEN**

Run the exact command from Task 1. Expected: all tests in `tests/scripts/pr-metadata-guard.test.ts` pass with no skipped tests or masked failure.
