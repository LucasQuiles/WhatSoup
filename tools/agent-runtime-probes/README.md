# Agent Runtime Probes

Secret-safe diagnostic probes for Claude Code, Codex, OpenCode, and Pi runtime
topology.

Default behavior is intentionally conservative:

- Print names, counts, paths, config keys, and env-var names.
- Do not print raw prompt bodies, auth values, cookies, tokens, or transcript
  contents.
- Do not mutate config.
- Avoid provider calls unless a script has an explicit `--run` or `--live`
  option documenting the tradeoff.

| `mutation_proof_chain.py` | CAPE proof-chain attestation spine (plane-agnostic): per-step linear hash chain with dual continuity invariant + chain-id-bound genesis, run-twice+perturbation determinism gate, structural delta-type classifier with fail-closed purpose↔delta constraints (defends structural≠semantic prompt poisoning), frozen closed-field `Attestation`/`Benefit`, and `verify_chain` emitting a metadata-only verdict (hashes/enums/booleans only) | No |
| `chain_authenticity.py` | CAPE proof-chain Slice 2 keyed-MAC producer authenticity (closes red-team F1/F3): a DETACHED HMAC-SHA256 over a domain-separated canonical message binding `chain_id` + record count + every record hash in order, with a caller-supplied producer secret; closes the gap that `mutation_proof_chain` proves INTEGRITY but not AUTHENTICITY (public genesis → anyone can mint a self-consistent chain). Refuses to sign an empty/unverified chain or empty key; verification is fail-closed and constant-time, reporting `mac_verified` only when the chain verifies AND the MAC matches AND bound metadata agrees; a tampered chain and a wrong key are indistinguishable (no forgery oracle). Detached design leaves the spine's closed field set, `verify_chain`, and the purity guard untouched; carries NO key-derived material (only an optional non-secret `signer_label`); metadata-only. Optionally BINDS a terminal-outcome marker into the MAC (`outcome=` / `--outcome`): a `measured`/`failed`/`completed` relabel, status swap, or stripped marker then breaks the signature — the authenticity layer that closes the relabel gap `chain_outcome_gate` (structural-only) cannot; the no-outcome path is byte-identical to the original scheme so older signatures still verify | No |
| `adoption_orchestrator.py` | CAPE proof-chain Slice 2 adoption tier: a PURE-PROJECTOR two-plane dispatcher that routes a plane's adoption request to its own gate and projects that gate's verdict WITHOUT recomputing it (reuses NO verdict logic — imports `paired_trial_harness`/`enricher_lift_gate` only for their `SCHEMA` constants). Reducer adopts ONLY through B3, enricher ONLY through the lift gate; a request carrying the OTHER plane's gate report is a `cross_plane_violation` forced to FALLBACK even if that foreign gate said eligible (the gate-confusion defense). Tags benefit by axis — cost (reducer) vs quality (enricher) — and never merges them (foreign-axis benefit fields are dropped). `adopt` is True iff routing is clean AND the plane's gate said `adoption_eligible` (strict bool, red-team F5); fail-closed on unknown plane / malformed or unrecognized report; metadata-only | No |
| `chain_lifecycle_gate.py` | CAPE proof-chain Slice 4 lifecycle gate over a spine-verified chain (leaves the closed `Attestation` field set + purity guard untouched). Closes red-team F2 (`chain truncation — any prefix is a valid chain`): `seal_chain` emits a detached terminal SEAL committing to chain_id + step_count + EVERY record hash in order (domain-tagged `CAPE-MPC-SEAL-v0`), and `verify_lifecycle` recompares it constant-time so truncation, extension, and same-length swaps are all detected against the seal. HONEST SCOPE: the seal is UNKEYED (closes accidental truncation + any truncation by a non-seal-holder); against a malicious re-sealing actor it must be signed — `chain_authenticity` keyed-MACs the same binding, and the two compose (structural commitment + authenticity over it). Also enforces a max-chain DoS cap (overlong chain → fail-closed) and no-op/expanding accounting (a run beyond `max_consecutive_noops` identity steps is a do-nothing loop → reject; expansion is reported, never auto-failed — an enricher legitimately expands). Reuses `mutation_proof_chain.verify_chain` (base must pass); fail-closed; metadata-only (hashes/counts/enums/reasons, never raw text) | No |
| `benefit_meter_gate.py` | CAPE proof-chain Slice 4 benefit-meter integrity gate (consensus §7 'non-operational meter ⇒ benefit=unknown'). A step may declare a `measured` benefit, but a measured claim is honest only if its METER was OPERATIONAL; a `measured` benefit whose meter is non-operational/degraded/absent (or undeclared) is an OVERCLAIM — its EFFECTIVE proof_class is downgraded to `unknown` (adoption-ineligible) and the chain FAILs. Defends the central thesis ('benefit is real'): without it a pipeline/adversary can stamp `measured` on a never-measured benefit and launder an unearned 'provably better'. heuristic/unknown benefits never claimed a measurement so meter status leaves them untouched (a meter entry on such a step is informational only). Validates the per-step meter sidecar fail-closed (out-of-range/duplicate/unknown-status → typed `malformed_meter_status`); reads only the declared benefit proof_class via `mutation_proof_chain` (no spine verdict logic); composes with verify_chain / chain_lifecycle_gate / chain_authenticity / adoption_orchestrator; metadata-only | No |
| `benefit_backing_gate.py` | CAPE proof-chain Slice 3 backed-benefit: the COMPLEMENT to `benefit_meter_gate` — where that asks "was the meter operational?", this asks "does the CLAIMED benefit value match what was MEASURED?". A `measured` benefit (value V, unit U) is BACKED only by a measurement for the same step, on unit U, from a real-measurement provenance (provider_truth provider-usage-fields or local_measured — NEVER a `heuristic`/chars-4 estimate, per USAGE-TRUTH), whose value matches V within `tolerance` (default 0.05). An unbacked / inflated / wrong-unit / weak-provenance claim is downgraded to `unknown` (adoption-ineligible) and the chain FAILs — closing the "measured: 0.4 was never measured or was inflated" hole at the heart of the 'benefit is real' thesis. heuristic/unknown benefits need no backing (measurement informational). Takes NORMALIZED measurement records (caller extracts them from usage_truth_probe / savings_vs_session_length_meter / A1 and tags provenance); typed `malformed_measurement` fail-closed; metadata-only | No |
| `substrate_measurement_adapter.py` | CAPE proof-chain Slice 3 live-extraction glue: maps measurement-substrate outputs into the normalized `{step_index, unit, measured_value, provenance}` records `benefit_backing_gate` consumes. Sources: `usage_truth` → provider_truth token_fraction REDUCTION from two usage_truth_probe metric dicts (total provider INPUT = input_tokens + cache_read + cache_creation — DISJOINT buckets, `output_tokens` excluded as it's the response not input economics; summing only input_tokens was the M3 bug); `deterministic_count` → local_measured count reduction (before−after); `heuristic_estimate` → heuristic (tagged so the backing gate rejects it as backing for a `measured` claim). Fails CLOSED: any absent/`unknown` provider field, or non-positive before-total, yields NO measurement (never a fabricated number). Binds to the substrate's actual field names (asserts its input-bucket subset of `usage_truth_probe._USAGE_INT_FIELDS` so a rename fails loudly); carries no verdict logic (the backing gate judges); typed `malformed_item`/`unknown_source` fail-closed; metadata-only | No |
| `experiment_harness.py` | CAPE Phase 3 bead 3.0 prediction-before-result interlock (anti-HARKing / anti-fabrication): a metered experiment (E2-E5) must `register_prediction` its SUCCESS CRITERION `{metric, comparator∈(lte,gte,lt,gt,eq), threshold}` IMMUTABLY before it runs (re-registering an identical prediction is idempotent; a DIFFERENT one for the same experiment_id is refused — `prediction_immutable` — so the goalposts can't move), then `write_result` evaluates the pre-declared criterion DETERMINISTICALLY against the observed metric. Fail-closed: a result with no registered prediction → `no_prediction`; a post-hoc edit to the stored criterion → `prediction_tampered` (re-derived domain-tagged hash mismatch). Separates experiment INTEGRITY (`overall_verdict` PASS iff prediction pre-existed + untampered + evaluable) from the SCIENTIFIC OUTCOME (`hypothesis_verdict` confirmed\|refuted\|inconclusive — a refuted hypothesis with PASS integrity is a valid result). experiment_id is filesystem-safe (refuses path traversal); typed `malformed_prediction` / `store_unwritable`; metadata-only | No |
| `experiment_e5_masker_bijection.py` | CAPE experiment E5 (masker bijection corpus) run THROUGH `experiment_harness`. Characterizes `prompt_sanitizer` over a corpus of overlapping/nested/duplicate/adjacent sensitive entities: PRODUCTION (longest-first, single-pass `mask`) yields zero residual leaks + an exact mask→rehydrate bijection (the pre-registered success criterion `production_residual_leaks == 0`); a shortest-first CONTROL diverges (proving span ORDER is load-bearing); and a B1 FALLBACK recovers the raw byte-identically via `raw_output_handle_protocol` when rehydration fails closed. HONEST finding (empirically verified vs the live SSOT patterns): pattern-based `residual_scan` is necessary-not-sufficient — it does not always flag the entity FRAGMENTATION the wrong order causes (e.g. an email that embeds a host gets only its host masked, leaving the local part exposed), so masker correctness rests on longest-first resolution. proof_class `direct_task_outcome`; metadata-only (counts/verdicts/hashes, never raw corpus values) | No |
| `experiment_e4_anchor_cliff.py` | CAPE experiment E4 (anchor/cliff sweep) run THROUGH `experiment_harness`. Sweeps a text through increasing compression and runs each variant through BOTH reducer gates — `compression_governor` (ratio cap) and `anchor_preservation_gate` (semantic survival). Keystone: the governor's ratio cap has a SEMANTIC BLIND SPOT — a compression UNDER the cap can still have dropped an anchor — and the anchor gate closes it, so the COMPOSED gate (governor AND anchor) adopts ZERO meaning-losing compressions (the pre-registered criterion `adoptions_with_anchor_loss == 0`, confirmed) while `governor_only_unsafe_adoptions` quantifies the blind spots the ratio cap alone would wrongly adopt (proving the anchor gate is necessary, not redundant). Emits a source-hashed safe-ratio + cliff-ratio CALIBRATION CANDIDATE tagged `local_measured` (FLOOR-PROVENANCE: eligible to inform a cap, never a research seed). proof_class `direct_task_outcome`; metadata-only (ratios/verdicts/counts/hashes, never raw text) | No |
| `experiment_e3_mask_cache_stability.py` | CAPE experiment E3 (mask cache-stability proxy) run THROUGH `experiment_harness`. Proves `prompt_sanitizer` masking is a cache-FRIENDLY transform — deterministic AND prefix-stable: `masked(prefix)` is a byte-prefix of `masked(prefix+suffix)` (placeholders assigned left-to-right with stable coreference counters, so an unchanged prefix masks to identical bytes regardless of what follows — the NECESSARY condition for provider prompt caching). Pre-registered criterion `prefix_stability_failures == 0` (confirmed); a CONTROL confirms the proxy is meaningful (a changed prefix is not a byte-prefix match). HONEST non-overclaim (E3-acceptance / USAGE-TRUTH): whether the provider actually cached requires provider usage (`cache_read_input_tokens`), unknown offline, so `provider_cache_hit_verdict` is `inconclusive_no_usage` — byte-stability is a proxy, NOT proof of a cache hit. proof_class `direct_task_outcome`; metadata-only | No |
| `experiment_e2_additive_through_b3.py` | CAPE experiment E2 (additive-through-B3 characterization) run THROUGH `experiment_harness`. Routes an ADDITIVE-only intervention (added uncached context tokens, no quality gain) through the B3 paired-trial reducer gate (`paired_trial_harness`): adding context drops the `cache_read_to_input_ratio`, so B3's `cache_not_worse` predicate fails and the intervention is NOT adoption-eligible (CACHE-NEUTRAL: additive context is not free when it churns the cache). Pre-registered criterion `additive_b3_adoptions == 0` (confirmed); a contrast improving-reducer arm (fewer tokens, better cache) IS adopted, showing B3 rejects on the cost/cache merits rather than rejecting everything. HONEST SCOPE (E2-PROOF): this CHARACTERIZES B3's rejection behavior — it does NOT prove plane separation (that is `adoption_orchestrator` + `two_plane_separation`, bead 4.3); the caveat is carried in the report's `scope` field. proof_class `blind_judge_comparison`; metadata-only | No |
| `output_redaction_auditor.py` | CAPE Phase 4 governance (bead 4.4): mechanically ENFORCES the estate-wide metadata-only invariant every probe claims. Walks a report's string values (recursively) and flags any carrying a HIGH-PRECISION sensitive shape — `{TOKEN, SECRET, PATH, REPO}` — via the SSOT patterns through `prompt_sanitizer.residual_scan` (TYPE + hash output, never the raw value); any leak FAILs fail-closed. PRECISION is load-bearing (it runs on EVERY report): the loose SSOT classes HOST/USER/ID match benign numeric metadata (the HOST pattern matches `0.4`) so they are DELIBERATELY excluded here and rely on field-name redaction instead — a clean report (ratios/counts/scores/hashes) always PASSes while a real path/secret/token leak is caught. HONEST SCOPE: detects sensitive SHAPES, not arbitrary raw prose/schema; a CAPE placeholder is masked (not a leak) and does not match. Reports field paths + leak types + value HASHES (the auditor is itself metadata-only); `audit_reports` worst-case corpus; proof_class `deterministic_verifier` | No |
| `shadow_harness.py` | CAPE Phase 4 governance (bead 4.2): provably side-effect-free shadow ("log-would-do") mode. Code run in shadow mode routes every side-effecting op through a `ShadowBoundary`; each of `{egress, write, inject, provider_call, external_call}` RECORDS the attempt (metadata-only) then RAISES `SideEffectError`. The record is written BEFORE the raise, so even a SWALLOWED SideEffectError leaves a trace — a pipeline that tries a side effect and ignores the error still FAILs the run. `run_shadow(fn)` verdict: no attempts → PASS/`no_side_effects`; ≥1 attempt → FAIL/`side_effect_attempted` (lists action types); a crashing run → FAIL/`run_error` (fail-closed). HONEST SCOPE: a boundary-OBJECT contract, not a syscall sandbox (a documented non-goal) — it proves no side effect occurs through the boundary; bypassing it to touch raw I/O is out of scope. Metadata-only (action types + summary HASHES, never raw targets/payloads); proof_class `deterministic_verifier` | No |
| `live_approval_gate.py` | CAPE activation-ladder MECHANICAL interlock: turns the `artifacts/live_approval.json` requirement from a procedural checklist item into a fail-closed gate. A live action (`shadow_run` / `e1_calibration` / `live_delivery`) is APPROVED only if a present, well-formed, in-scope, attributed, unexpired approval artifact authorizes exactly that action; the default is BLOCKED and every error path fails closed (absent/malformed/wrong-schema/out-of-scope/missing-grantor/missing-reason/invalid-or-zero-width-window/not-yet-valid/expired/ref-mismatch → a closed-vocabulary reason code). Performs NO live action itself (decides approved\|blocked only); offline and DETERMINISTIC (the caller supplies `now_epoch`; the probe never reads the wall clock); optionally binds the artifact's `plan_ref` against an `expected_ref` (anti-stale-reuse). Metadata-only (decision/reason-code/scope/window/grantor/checksum, never the artifact's free-text reason or secrets); CLI exits 0 only on approval, 2 when blocked | No |
| `cape_shadow_runner.py` | CAPE activation-ladder step 2: runs the REDUCER plane in log-would-do (shadow) mode to produce, with a mechanically-proven ZERO-side-effect guarantee, the two numbers that decide live adoption — would the plane ADOPT a reduction, and the PROVIDER-TRUTH token saving it would yield. The reducer pipeline (`compressor_adapter.adapt`, a pure ADOPT\|FALLBACK decision) runs inside `shadow_harness.run_shadow`; a clean run touches NO `ShadowBoundary` side effect (egress/write/inject/provider_call/external_call) → PASS/`no_side_effects`. | `cape_shadow_enricher.py` | CAPE activation-ladder step 2 (enricher half): runs the ENRICHER plane in log-would-do (shadow) mode. ## Redaction Policy

The probes redact values for keys containing:

```text
token, secret, key, password, credential, auth, cookie, header, client_id,
tenant_id, url
```

They still report key presence and safe names because topology work needs to
know that an auth route exists without seeing the value.

`config_surface_doctor.py` is intentionally not a broad filesystem crawler. It
includes selected control planes plus direct skill, agent, plugin, theme,
script, wrapper, launchd, directory, and generated-workspace policy surfaces.
Missing managed-policy candidates are omitted by default and included only with
`--include-missing`. Add new paths deliberately with a source class and
redaction posture.
